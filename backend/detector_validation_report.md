# ScaleFlow Detector Validation Report
**Date:** 2026-06-03

## Executive Summary
This report investigates the 0% True Positive (TP) rate for the structural and content classifiers (Handwriting, Signature, Table) on validation categories F, G, and H.

## Detector Analysis

### 1. Are they actually firing?
Yes. The detectors (`_detect_signature`, `_detect_table`, `_compute_handwriting_score`) are firing correctly during the `evaluate_document` phase. However, they all return `False` or below-threshold scores for the test documents.

### 2. Are the thresholds incorrect?
The thresholds are generally acceptable for real-world document heuristics:
- **Table**: Requires $\ge 3$ horizontal and $\ge 2$ vertical intersecting Hough lines.
- **Signature**: Looks for a curvy, low-circularity blob with area $> 200$ pixels in the bottom 30% of the page.
- **Handwriting**: Uses structural texture analysis (connected component coefficient of variation, stroke width variance).

### 3. Is the evaluation framework incorrect?
**Yes.** The evaluation framework is completely invalid.
- **Category F** (The Billion Dollar Sure Thing) was generated as pure text (`d.text(...)`) using FPDF in the `run_preprocessing_experiments.py` script. It contains no signatures and no tables. Yet, the `ground_truth` matrix expected `has_signature: True` and `has_table: True`.
- **Category G** (Mixed Printed and Handwriting) was generated with a single computer-drawn blue bezier curve (`d.line(...)` with 4 points). This thin vector line does not resemble the thick, variable-width, blob-like contour of a real human signature at 72 DPI, failing the signature circularity and area heuristics.
- **Category H** (Handwritten notes) was generated by drawing mathematical sine waves (`int(math.sin(x) * 15)`). Sine waves have perfect uniform thickness and spacing. The handwriting detector looks for irregular stroke widths and spatial ink density irregularity (which real handwriting has). Sine waves completely bypass these heuristics.

## Conclusion
The detectors have "zero demonstrated usefulness" in the previous report **because they were tested against fake, algorithmically generated drawings that do not represent real-world document structures**. The false negatives are a failure of the test data (`generate_dataset()`), not necessarily the detectors themselves. To accurately validate the detectors, they must be tested against real scanned document datasets (e.g., RVL-CDIP or custom real-world PDFs) rather than FPDF vector drawings.
